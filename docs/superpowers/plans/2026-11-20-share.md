# Share Button Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a lightbox Share button (OS share sheet, original file) with a Download fallback, and make the app usable behind `tailscale serve` HTTPS.

**Architecture:** `server.py` only changes the CSRF origin check in `read_json_body` (accept `Host` or `X-Forwarded-Host`). The static client prefetches the original of the open item (at most 30 MB) as a Blob so the click handler can call `navigator.share` synchronously. HTTPS comes from `tailscale serve` outside the app; the README documents the manual setup.

**Tech Stack:** Python 3 stdlib (`http.server`, `unittest`), plain HTML/CSS/JS (classic scripts sharing globals: `app.js`, then `select.js`), scratch playwright-core harness for browser checks.

**Spec:** `docs/superpowers/specs/2026-11-20-share-design.md`

## Global Constraints

- No new dependencies; no build step. The app stays plain HTTP on `0.0.0.0:8765`; no certificates in the app.
- Size limit: `SHARE_MAX = 30 * 1024 * 1024` bytes (31457280), compared with item `size` as `size <= SHARE_MAX` (exactly 30 MB is shareable, one byte more is not).
- Exact UI strings: button labels `Share`, `Preparing…` (single ellipsis character), `Too large to share`, `Download`; error toast `Couldn't share`. A cancelled share sheet (`AbortError`) shows nothing.
- Share is offered only when `window.isSecureContext` and `navigator.canShare?.({files: [file]})` is true; otherwise Download (`<a download="<name>" href="/media/<id>?k=<k>">`, via `url('media', it)`).
- Always the original bytes; the File gets the item's real `name` and the response's `Content-Type` as `type`.
- One prefetched Blob at a time; navigating or closing aborts the in-flight fetch (`AbortController`) and drops the previous Blob.
- Origin guard: accept when `urlparse(Origin).netloc` equals `Host` or `X-Forwarded-Host`; otherwise 403 `Forbidden origin`; JSON content-type rule (415) unchanged; a request with no `Origin` header is accepted as before.
- Never run `server.py`'s `main()` on port 8765, never touch the live checkout (`/mnt/c/Users/rafavcc/iCloudDrive/Programming/projects/app_civitai`), never run `tailscale serve`/`up`/`set` (only `tailscale serve --help`), never write to `~/.cache/civit-rv` from tests. Browser checks use a scratch harness (outside the repo) that imports `server` with temp paths on an ephemeral port.
- Run tests: `python3 -m unittest discover -s tests` from the worktree root.

## Review Focus

1. Safari transient activation: the click handler must call `navigator.share` in the same tick, with no `await` before it (a prefetch-then-await design silently fails on iOS). Pinned by T2 `synchronous share call`.
2. A slow prefetch for item A finishing after the user moved to item B: it must not enable the button or set the File for B. Pinned by T2 `stale prefetch ignored after navigation`.
3. The origin guard must not become a hole: `X-Forwarded-Host` only widens the allowed set; a mismatched Origin is still 403 whatever else is sent. Pinned by T1 `test_origin_mismatching_both_headers_is_403`.
4. The 30 MB boundary and memory: exactly `SHARE_MAX` is shared, `SHARE_MAX + 1` never triggers a `/media` fetch. Pinned by T2 `size boundary`.
5. A failed prefetch (404 stale key, 503 downloading for an online-only iCloud file, network error) must not leave the button stuck on "Preparing…" or block the UI; it falls back to Download. Pinned by T2 `failed prefetch falls back to download`.

- Test: scratch playwright-core check (outside the repo, in the scratchpad dir), described below

**Interfaces:**
- Consumes: `url('media', it)`, `listed`, `cur`, `toast(msg)` from `app.js`; item fields `name`, `size`, `id`, `k`; `/media/<id>?k=` from the server (unchanged).
- Produces (globals in `select.js`):
  - `const SHARE_MAX = 30 * 1024 * 1024;`
  - `prepareShare(it) -> void`: resets state, aborts any previous prefetch, then sets the UI: size > `SHARE_MAX` → `#sharebtn` "Too large to share" disabled, `#dlbtn` visible; no pre-check support (`!isSecureContext`, or `navigator.share`/`navigator.canShare` not functions) → `#sharebtn` hidden, `#dlbtn` "Download" visible; otherwise `#sharebtn` "Preparing…" disabled, `#dlbtn` hidden, and starts `fetch(url('media', it), {signal})`. On success builds `file = new File([blob], it.name, {type: response Content-Type})`; if `navigator.canShare({files: [file]})` is true → `#sharebtn` "Share" enabled, else switch to Download. On non-OK response or fetch error (not an abort) → Download. Results are applied only if the item is still current (token compare), never for an aborted or superseded prefetch.
  - `cancelShare() -> void`: aborts the fetch, drops the Blob/File reference, resets both buttons.
  - Click handler on `#sharebtn`: synchronous `navigator.share({files: [file]})` (no `await` before the call), then `.catch(e => e.name !== 'AbortError' && toast("Couldn't share"))`.
